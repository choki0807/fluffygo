# FluffyGo 项目介绍文档

## 1. 项目定位

FluffyGo 是一个面向城市养宠用户的 AI 本地路线智能规划产品。它聚焦“现在就出发”的真实场景：用户只需要输入一句话，例如“我现在在南京新街口，想带一只中型犬出门 2.5 小时，不想太挤，预算 100 元以内”，系统即可结合当前位置、宠物体型、预算、天气/拥挤风险和周边目的地，生成可执行、可比较、可交易、可反馈的带宠本地生活路线。

项目选择“带宠出行”作为切入点，是因为这类需求天然不是单点搜索问题。用户并不是只想找一家店，而是想判断“从哪里出发、先去哪散步、哪里能停留、哪里能消费、是否适合中型犬、下雨怎么办、预算是否合适”。FluffyGo 将这些分散在地图、点评、宠物频道和社交平台里的判断，整合成一条可执行路线。

## 2. 赛道匹配

本项目匹配“现在就出发：AI 本地路线智能规划”赛道。

核心匹配点包括：

- AI 路线规划：将自然语言输入解析为位置、时间、预算、宠物体型、偏好和避免项，并生成多条候选路线。
- 本地生活场景：路线串联公园/绿地、咖啡/轻食、宠物洗护、用品补给、雨天备选等本地生活节点。
- 即时出发决策：通过可行性评分、风险雷达、路线对比和真实地图步行路线，帮助用户判断当前是否适合出发。
- 交易连接：每个路线节点都可以承接美团咨询、团购、预约洗护、用品补给、代溜服务等动作。
- 数据闭环：用户到店反馈、宠物友好核验和社区路线情报会反哺后续推荐。

## 3. 产品链路

当前 Demo 已形成完整链路：

1. 用户在首页查看当前位置周边宠物友好目的地。
2. 用户输入一句带宠出行需求。
3. 后端解析地点、时间、预算、宠物体型、偏好和避免项。
4. 系统生成推荐路线，并展示站点、风险、可行性评分和交易动作。
5. 用户可以切换低压力、雨天、省钱、服务补给、纯散步等路线。
6. 地图展示起点、途经点和终点，并接入百度步行路线。
7. 用户可提交到店反馈，影响宠物友好证据和后续推荐排序。
8. 个人页沉淀路线收藏、到店确认记录、路线核验贡献和宠物出行档案。

## 4. 技术栈说明

| 模块 | 技术/工具 | 作用 |
|---|---|---|
| 数据采集 | Python, Requests, python-dotenv | 调用百度地图 Place API，采集 POI 样本 |
| 数据处理 | Pandas, CSV, JSON | 清洗 POI、生成 raw CSV、shortlist CSV 和 Demo JSON |
| 后端服务 | FastAPI, Uvicorn, HTTPX | 提供路线规划、健康检查、Demo 数据、实时 POI、反馈提交等 API |
| 推荐逻辑 | 规则引擎 + LLM-ready 架构 | 稳定解析用户意图、生成路线，同时预留真实 LLM 增强接口 |
| 地图能力 | 百度地图 Place API, JavaScript API, WalkingRoute | 采集地点、展示地图、生成真实步行路线 |
| 前端 Demo | HTML, CSS, JavaScript | 构建移动端优先的产品原型页面 |
| MVP 验证 | Streamlit | 早期快速验证数据结构和产品链路 |
| 数据闭环 | 本地 JSON/内存状态 + POI feedback API | 模拟用户反馈对宠物友好证据和排序的影响 |
| 测试验证 | test_backend.py | 验证多区域、预算、路线类型、反馈闭环和推荐降权逻辑 |

技术架构上，项目采用“规则稳定兜底 + LLM 可增强”的方式。这样可以保证黑客松现场 Demo 不依赖不稳定的外部模型，同时又保留真实 LLM 接入路径。API Key 不暴露在前端，所有智能规划逻辑通过 FastAPI 后端统一处理。

## 5. 核心创新点说明

### 5.1 从“找一个点”升级为“规划一条可执行路线”

传统本地生活搜索多以 POI 列表为中心，而带宠出行的真实需求是组合式的：开放空间、消费点、服务补给、雨天备选和返程便利都需要同时考虑。FluffyGo 将 POI 组织成路线，让用户直接获得“可以怎么走”的方案。

### 5.2 宠物友好不是单一标签，而是证据体系

项目没有简单展示“宠物友好/不友好”，而是拆成空间类型、犬型适配、外摆状态、室内准入、人流压力、证据来源、用户反馈等多个维度。用户可以通过“查看依据”理解为什么系统认为某个点更适合带宠停留。

### 5.3 推荐结果会随着输入变化而变化

Demo 已覆盖多个高频场景：

- 只想去公园，不想消费：生成纯散步路线，不强行出现咖啡。
- 预算只有 30：优先免费/低消费路线。
- 下雨了：切换雨天备选线，并明确哪些点只是备选。
- 想顺路洗护：生成服务/补给线，并出现预约动作。

这使推荐不再像静态模板，而是能体现用户预算、偏好和约束。

### 5.4 反馈闭环影响推荐排序

用户的“可以带狗”“只限外摆/小型犬”“不可带宠”等反馈会影响宠物友好证据和后续路线排序。近期负反馈会让 POI 降权并退出主推荐，正反馈会提升证据层和推荐权重。这是项目从 Demo 走向真实产品的关键能力。

### 5.5 路线资产与社区形成长期使用理由

个人页沉淀路线收藏、到店确认记录、路线核验贡献和宠物出行档案。社区模块保留用户之间的路线情报分享，代溜服务作为商业化延展能力。这让 FluffyGo 不只是一次性规划工具，而是可以逐步沉淀用户资产和本地生活数据的平台。

## 6. 商业价值说明

### 6.1 拓展美团宠物频道的高频入口

传统宠物频道更偏洗护、医疗、用品等低频明确需求。FluffyGo 将“日常遛狗、周末短逛、雨天出门、顺路补给”等高频场景纳入产品入口，有机会提升宠物相关本地生活服务的打开频次。

### 6.2 将路线变成连续交易链路

一次带宠出行可以自然串联多个交易节点：

- 咖啡/轻食/餐饮：查看团购、电话咨询、预约座位。
- 宠物洗护：预约洗护、查看服务价格。
- 宠物用品：顺路补给、购买消耗品。
- 代溜服务：用户无法亲自出行时，将路线转为履约订单。

相比单点列表，路线场景更容易承接连续消费和即时决策。

### 6.3 沉淀高质量宠物友好数据资产

宠物友好标签具有强本地性和动态性。外摆是否开放、是否允许中型犬、周末是否拥挤、地铁口是否适合经过，这些信息很难仅靠商家静态资料判断。FluffyGo 通过用户反馈和路线核验，让平台沉淀更细颗粒度的本地生活数据资产。

### 6.4 增强平台差异化体验

如果用户只需要“查一家店”，地图和点评都能完成。但如果用户需要“现在带狗去哪更合适”，FluffyGo 可以提供更强的决策体验：路线、风险、预算、宠物压力、交易动作和反馈证据一起呈现。这是从信息展示到智能决策的升级。

## 7. 当前 Demo 完成度

当前项目已经具备：

- 南京新街口、鼓楼、秦淮、玄武多区域路线规划基础。
- FastAPI 后端与静态前端联动。
- 百度地图真实步行路线展示。
- 多路线对比、风险雷达、可行性评分。
- 宠物友好证据体系与到店反馈闭环。
- C 端社区情报与代溜服务概念。
- 个人路线资产页。
- 后端测试脚本，可验证预算、雨天、洗护、纯散步、反馈降权等场景。

## 8. 后续优化方向

1. 接入真实 LLM：增强自然语言理解、推荐解释和多轮调整能力。
2. 扩大数据覆盖：从当前 Demo 区域扩展到更多城市和更多宠物友好商户。
3. 强化商家核验：引入商家侧宠物友好认证、犬型限制、外摆状态和营业时段。
4. 完善交易闭环：将“查看团购、预约洗护、电话咨询、代溜下单”做成真实交易入口。
5. 增强社区真实性：引入图片、签到、路线轨迹和用户信用，提升反馈可信度。

## 9. 一句话总结

FluffyGo 的核心价值不是再做一个宠物友好地图，而是把带宠出行从“单点搜索”升级为“可执行、可交易、可反馈的 AI 本地生活路线”。
