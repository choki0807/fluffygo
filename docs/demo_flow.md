# Demo 演示流程

## 目标

用 2 分钟让面试官看懂 FluffyGo 的产品价值和工程链路。

## 演示前准备

进入项目目录：

```powershell
cd C:\Users\Administrator\Documents\Codex\2026-04-26\prd-demo
```

启动静态前端：

```powershell
.\start_demo.ps1
```

打开：

```text
http://127.0.0.1:8000/stitch_demo.html
```

后端健康检查：

```text
http://127.0.0.1:8001/api/health
```

## 演示步骤

1. 首页说明

   FluffyGo 是一个 AI 宠物友好本地生活消费路线助手，不是简单找一个店，而是为带宠用户规划一条可以走、可以停、可以消费、可以调整的路线。

2. 展示用户输入

   默认输入包含地点、时间、宠物体型、拥挤偏好、咖啡需求和预算。

3. 点击“生成路线”

   前端调用 FastAPI 后端 `/api/plan-route`，展示 AI 解析结果，包括出发位置、可用时间、宠物类型、宠物体型、预算、偏好、避免项和消费意图。

4. 展示路线结果

   路线由 2-3 个站点组成，每个站点不是一段大文本，而是结构化 POI 卡片。

5. 展示出行决策模块

   重点讲：

   - 出行可行性评分：判断是否适合现在出发；
   - 风险雷达：提前识别人流、室内准入、犬型适配、天气和规则不确定性；
   - 路线对比：主路线、低压力路线、雨天备选路线不是固定结果，而是可比较的选择。

6. 展示 POI 卡片

   重点讲：

   - 宠物友好状态
   - 可信度
   - 宠物压力等级
   - 风险提示
   - 美团交易动作

7. 点击调整按钮

   - “现在太挤了”：切换低压力路线。
   - “下雨了怎么办”：切换雨天备选路线。
   - “预算只有 60”：展示预算降级策略。

   这里可以强调：这不是单纯前端切换，而是经过后端路线规划接口返回结构化结果；如果后端没开，前端仍有 fallback，不影响演示稳定性。

8. 讲 C 端社区和代溜服务

   说明 FluffyGo 不只是推荐路线，还可以让用户互相反馈“能不能带宠”“外摆是否开放”“人是否太多”，并进一步连接 C 端代溜服务，形成新的本地生活服务供给。

9. 讲商业价值

   FluffyGo 将带宠出行转化为本地生活组合消费路线，可连接咖啡、餐饮、洗护、用品补给等交易入口，并沉淀宠物友好标签。

## 30 秒项目总结

这个项目从 POI 采集开始，经过规则清洗、宠物友好打标、路线角色划分和结构化 JSON 建模，最终用前端 Demo 展示一个完整的本地生活 AI 路线助手。它既能体现数据处理和工程实现，也能体现产品判断和业务价值。
